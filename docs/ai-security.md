# ThreatGraph X - Grounded AI & LLM Security Architecture

## 1. Principles of AI in Defensive Security
ThreatGraph X embeds an optional AI-assisted analytical copilot designed with strict safety boundaries:
1. **Zero Direct Execution**: The AI assistant cannot execute shell commands, alter firewall rules, or make unmonitored infrastructure changes.
2. **Deterministic Evidence Grounding**: Every claim generated by the assistant must cite explicit Event IDs (`EVT-...`), Alert IDs (`ALT-...`), or Evidence Hashes.
3. **Refusal Under Uncertainty**: If available forensic telemetry is insufficient to establish a hypothesis, the model explicitly responds: *"Insufficient evidence in the current investigation."*
4. **Adversarial Input Isolation**: Raw event data and logs are treated as untrusted text wrapped in strict XML tags to prevent Prompt Injection attacks.

## 2. Evidence Retrieval-Augmented Generation (RAG) Architecture
```
Analyst Question -> Intent Extraction -> Graph & SQL Retrieval -> Context Sandbox -> LLM -> Evidence-Citing Summary
```

## 3. System Prompt Guardrails
The system prompt explicitly mandates:
- Refuse requests to generate offensive exploits or reverse-engineer payloads for attack purposes.
- Never invent IOCs, MITRE ATT&CK technique IDs, or timestamps not present in the supplied retrieval context.
- Frame all findings in probabilistic, defensive terminology ("Activity observed is consistent with...").
